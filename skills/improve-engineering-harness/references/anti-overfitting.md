# Anti-overfitting

Harness changes can overfit one memorable failure.

Avoid overfitting by:

- minimizing the failure to its mechanism rather than preserving incidental wording;
- testing more than one surface form when the rule is semantic;
- including control tasks that should not trigger the new behavior;
- preferring structural checks over keyword lists when structure is available;
- avoiding proper nouns or project-specific terms in generic Skills unless necessary;
- testing false-positive behavior for safety/routing gates;
- refusing a new universal rule from one low-severity anecdote.

A good improvement generalizes to the causal class while remaining quiet outside it.
